# Decisions and trade-offs

Why this build is shaped the way it is, what each choice costs, and what would change in production.

| # | Decision | Why | Trade-off accepted | In production |
|---|---|---|---|---|
| 1 | **Land the ERP as change-data-capture files** shaped like Yardi Voyager tables, in the style of Qlik Replicate (`header__operation`, `header__timestamp`) | This is how many real estate firms already replicate their ERP. AUTO CDC turns the files into SCD Type 1 dimensions and an SCD Type 2 lease history with no merge code. | Synthetic files, no live connector. | Lakeflow Connect or the firm's existing replication tool, writing the same file format. |
| 2 | **Extract lease terms inside the Lakeflow pipeline** with `ai_parse_document` + `ai_extract`, not in a separate service or notebook | The extraction inherits lineage, tags and masks. Auto Loader only processes new PDFs, and failures retry like any other pipeline step. | Less control than a hand-written prompt through `ai_query`; mitigated by measuring every field against ground truth. | Same pattern; add a reviewed sample of real leases as the accuracy benchmark. |
| 3 | **A typed `ai_extract` schema with field descriptions** instead of free-form JSON from an LLM | Typed output, no parsing code, and the descriptions are the prompt. Fixing one description raised escalation-type accuracy from 48% to 100%. | Deeply nested structures come back as arrays of `{value}` objects and need flattening. | Version the schema with the pipeline; review the descriptions with the lease-admin team. |
| 4 | **Abstract a risk-weighted subset** (116 of 391 leases: everything expiring within 24 months plus the 25 largest tenants) | This mirrors how asset managers prioritize, and it keeps extraction cost proportional to risk. | Clause questions don't cover every lease. Genie reports an *abstraction coverage* measure and never treats a missing abstract as "no clause". | Abstract the full portfolio once, then incrementally on new and amended leases. |
| 5 | **Measure accuracy against generated ground truth** | The generator writes an answer key for every PDF, so accuracy is a number, not an impression. It caught a PDF layout bug that left every field NULL. | Clean, machine-generated PDFs overstate real-world accuracy. | A reviewed sample of real, scanned leases; the review queue feeds corrections back as labels. |
| 6 | **Use H3 cells for proximity** (k-rings at resolution 9), plus `h3_coverash3` + `st_covers` for neighborhood membership | Spatial joins become equality joins on a cell ID, so 4M POIs and 30.8M buildings are cheap. Exact geometry is used only where the boundary matters. | A k-ring is an approximation: "about 1 km", not exactly 1 km. | Same; add licensed parcel and comps data (ATTOM, Cotality) through Delta Sharing. |
| 7 | **Give Genie trusted SQL functions for spatial questions** (`assets_near_deal`, `assets_near`, `competitors_within`) | Genie gets the spatial logic right every time instead of improvising it. Benchmarks failed when Genie joined on H3 cells directly; join specs and column notes fixed it. | New spatial question types need a new function. | A small, versioned library of trusted functions, owned by the BI team. |
| 8 | **Define the measures once in metric views** (ABR, WALT, % of ABR expiring, occupancy, abstraction coverage) | One definition for Genie, SQL and dashboards, so "WALT" means the same thing everywhere. | Metric-view YAML is one more artifact to maintain. | Same; the metric views become the governed KPI contract. |
| 9 | **Enforce fund security in Unity Catalog** (a row filter on `fund_id` driven by a mapping table, plus column masks on tenant contacts) instead of in the app | One rule for Genie, SQL and the app. Adding a fund team is one row in a table. | Synced Lakebase tables need an unfiltered source (`property_360`), so the app is the access boundary for Lakebase reads. The demo groups are workspace-local, so analyst table grants would need account groups. | Account-level groups; Postgres roles per group for Lakebase reads, or route fund-sensitive reads through the SQL/Genie path. |
| 10 | **Serve the app from Lakebase**, with snapshot-synced tables and a native `app.abstract_review` table for corrections | Millisecond reads (2.8 ms average) and transactional writes, which a warehouse is not built for. | Snapshot sync means the app is as fresh as the last pipeline run. Corrections reach gold on the next update, not instantly. | Triggered or continuous sync for the tables that change intraday. |
| 11 | **Write corrections back to Postgres and merge them into Delta**, rather than letting the app write Delta directly | The app gets a normal OLTP write path. The pipeline applies approved corrections with full lineage, and every correction keeps its reviewer and timestamp. | Two hops (Postgres → Delta → gold) instead of one. | Same pattern; schedule the merge with the pipeline. |
| 12 | **A gradient-boosted classifier for renewal propensity**, registered in Unity Catalog | Small tabular data, fast to train, handles mixed features, explainable through feature importance. | Labels are synthetic (a documented logistic function), so the AUC of 0.71 shows the plumbing works, not real predictive power. Expected vacancy loss assumes 9 months of downtime. | Train on actual renewal outcomes; add Lakehouse Monitoring on `renewal_scores`; let asset managers set downtime by market. |
| 13 | **Score Genie with benchmark questions** that carry known-good SQL (11 questions, 10 pass and 1 partial) | Genie quality becomes a regression test, re-run after every change to instructions, tables or functions. | Benchmarks only cover the questions someone thought to write. | Grow the set from real user questions, and review failures weekly. |
| 14 | **Streamlit for the app** | The fastest route to a working map, review queue and Genie chat in Python. | Less polished than a React front end. | React (or APX) once the workflows settle. |
| 15 | **Overture Maps for market context**, downloaded publicly | Open license (CDLA Permissive 2.0 / ODbL), global coverage, places, buildings and boundaries. Marketplace access wasn't available in this workspace. | No ownership, parcel, tax or comps data. Neighborhood polygons are dense only in Salt Lake City. | ATTOM or Cotality through Marketplace / Delta Sharing, plugged into the `neighborhood_enrichment` contract. |
| 16 | **One Declarative Automation Bundle, serverless everywhere** | One `bundle deploy` builds the pipeline, jobs and app. No clusters to size, and nothing idles. | The serverless environment has to carry the notebook dependencies. | Same bundle with `dev`, `test` and `prod` targets, promoted from CI. |
